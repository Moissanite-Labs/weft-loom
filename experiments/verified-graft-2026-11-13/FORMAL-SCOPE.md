# Formal specification and trusted boundary

The implementation uses pinned Lean 4.35.0 and exact unbounded `Int` arithmetic. The host accepts
bounded JSON integers only. It does not accept proof text, source code, paths or imports from a
proposal. Concrete certificate files are generated by a trusted template and checked with ordinary
`decide`, never `native_decide`.

## Deployment contract

A matrix has two rows and six integer coordinates per row. The declared host entries are in −2..2.
Proposal deltas are in −4..4 and have squared Frobenius norm at most 192. These bounds are checked
in both Python and Lean. Protected bases contain exactly three unique signed coordinate directions
for the compatible case or all six for the saturated case. The three native directions must be
covered by the protected span.

A graft replaces the root with host plus delta and must preserve its outputs on every protected
basis vector. A fork is allowed only in the saturated case and requires a nonzero delta: the root
stays unchanged and exactly one specialist is host plus delta. An abstention requires a zero delta.
The concrete certificate binds the resulting root, optional specialist, native/new router and cell
count to the declared mode. Native requests always use the root. New requests use the specialist
only in fork mode.

Invalid mathematical actions can produce a valid certificate that `allowed = false`. These return
`kernel_checked=true` but `accepted=false`. A compiled rejection is not permission to deploy.
Malformed data is rejected by host validation before constructing Lean source.

## Global protected span

`VerifiedGraft.span_retention` proves preservation for every finite integer-weighted combination of
protected vectors, assuming equality on those vectors. Each accepted deployment includes its own
`VerifiedGraftConcrete.checked_basis` theorem and a specialized `registered_span_retention` theorem.
This establishes preservation throughout the registered integer span, rather than only the finite
test examples. Because the basis is signed coordinate directions, this covers every integer input
supported in those directions. In the saturated case it covers all six-dimensional integer inputs.

The generic span theorem uses Lean's standard `propext` and `Quot.sound` logical axioms through
integer algebra and normalization. The compiler's actual dependency report is checked against that
explicit set. It uses no custom axiom or admitted theorem. Every concrete deployment, score and
decision certificate separately must report an empty axiom set. These are distinct claims. The
generic theorem is not labeled axiom-free.

`VerifiedGraft.conflict_witness` is axiom-free: if the host and target outputs differ at an input,
every candidate that preserves the host there fails the target there. Each conflict artifact checks
that concrete difference and instantiates a `universal_conflict` theorem for every candidate matrix.
The caller must establish that this witness belongs to the protected domain. The returned artifact
explicitly states that condition.

## Scores and confirmation

Score certificates bind a concrete deployment, target matrix, named input batches and reported
integer squared errors. They evaluate the selected native/new route exactly. False reported scores
fail compilation. The adoption certificate proves that the declared decision equals the rule: strict
improvement and at least 10% lower SSE on both selection A and fresh confirmation B. Correctly
rejecting an overfitter is a successful decision certificate, with `adopted=false`.

The score gate does not choose a provisional candidate or establish that confirmation inputs were
hidden. The runner must rank on A, evaluate only that provisional choice on B, prohibit B reranking,
and bind all artifacts to the frozen inputs. A zero score on arbitrary samples alone is not labeled
a proof of complete new-task equivalence. Exact coefficient equality or sufficient independently
established spanning conditions are needed for that stronger interpretation.

## What remains trusted

The Python validators and templates, filesystem binding, actually executed compiler and standard
library, input generation, experiment selection/routing orchestration, operating system and hardware
remain trusted implementation components. Generated certificates prove their explicit mathematical
statements. They do not prove that Python or an external machine performed a physical action. Hashes
establish retained artifact identity, not correctness or authentication against a malicious host
owner.

Forking introduces a second cell and an explicit task-ID router. It does not show that one
context-blind operator satisfies conflicting tasks, nor that a clone provides throughput benefits.
The model is a fixed-feature linear readout. The proof does not extend to arbitrary nonlinear
Jacobian projections or unseen changes to feature semantics.
