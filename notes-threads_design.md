## Phase-by-phase build specification emerging from both threads

The following work can be scoped into issues without adopting historical implementation claims. Each gate describes a reviewable result; no calendar prediction is implied.

### A. Existing-browser foundation — feasible now

**Dependencies:** current Aywa/WebGPU/Canvas2D seeds; present Chrome; fixture data with explicit provenance; no model dependency. **Output:** independent renderer contract with typed telemetry and separate aesthetic parameters, stable layout/labels, inspectable source→metric→visual legend, functioning fallback, keyboard/semantic reading layer, reduced-motion behavior, bounded resize/DPR handling and clean teardown.

**Acceptance:** real Chromium and owner-Mac runs show root/nested-path refresh, bounded inputs, out-of-order/bad/empty/HTTP failure rejection and recovery; visual geometry agrees with known fixtures at several sizes; hidden-tab work is suspended/bounded; frame-time/RAM/power measured instead of locked120FPS promises. Root's existing PR46 covers a subset of refresh behavior. Preserve the biological style as expressive vocabulary and make data interpretation explicit.

### B. Useful organization telemetry — feasible implementation plus definition work

**Dependencies:** a documented collector permission scope and host publication rules. **Output:** versioned metric schema with source/revision/window/units/formula/status; paginated GitHub collector and local-git adapter; meaningful missing/derived/fixture distinctions; canonical packet encoding and producer sequence/freshness; per-repo rather than one-global-metric coverage.

**Acceptance:** recorded fixture repositories exercise maintainer identity, external author identity, additions/deletions/renames, bots, zero/one/many contributors, labels, PR/issue distinction and unavailable external activity. Reconcile total counts independently. A fix-link graph preserves evidence and uncertainty instead of labeling people by an inferred quality score. This builds the user's five analytics requests while avoiding false precision. Formal definition choices precede ranking or economic use.

### C. Modular aesthetic exchange — feasible now locally; shared writing needs infrastructure

**Dependencies:** renderer style-input schema and strict slice parser. **Output1:** in-page library, import/export, attribution/provenance, N-way weights, local persistence, preview/reset and independently selectable features; defaults do not mutate other users' chosen styles. **Acceptance1:** roundtrip preserves canonical identity; invalid/nonfinite/unbounded data rejected; zero/negative weights and opposed hues have defined behavior; interactions remain legible and operable. Local export/import requires no new server/repository.

**Output2:** reviewed shared slice registry, explicit author identity, version/history, duplicate/fork handling and contribution workflow. **Acceptance2:** two concurrent writers don't overwrite each other; write requires explicit user intent and correct repo scope; revoked/expired credentials fail safely; no secrets cross public CORS proxies; approval/publication rules are enforced. A branch/PR contribution is a useful first shared workflow; a brokered OAuth service is a later option. Define whether communal taste influences defaults, suggestions or all users before enabling global ripple behavior.

### D. Learning-by-experience — feasible alongside A–C

**Dependencies:** trustworthy visual/metric contracts. **Output:** the requested technical mind palace: interaction telemetry, model, uniforms and shader shown as connected functional parts; live sliders demonstrate each stage and reveal data/provenance; original lore and biology retained as metaphor. **Acceptance:** each displayed causal claim corresponds to a real executed mechanism; a learner can distinguish a model decision from a heuristic/simulation and trace one value end-to-end. This can be valuable even before a real local model exists.

### E. Local decision model — experiment, then optional tooling

**Dependencies:** reproducible heuristic baseline, explicit preference controls, pinned model/runtime provenance, realistic browser memory/download budget. **Output:** isolated model adapter with schema, worker lifetime, finite/bounded decisions, confidence/fallback policy, local caching and offline test; benchmark corpus reflecting task intent rather than assumed emotion.

**Acceptance:** compare quality/calibration, decision latency percentiles, cold download/start, steady RAM/frame impact and user preference against the simple baseline on owner's Chrome/M1. Inference never runs per pixel or per animation frame; explicit actions and bounded smoothing govern updates. Record CPU/WASM and WebGPU results separately. A421M label does not imply tiny assets or unbounded buffer availability. Online training is a different experiment from inference and needs its own retained-performance gate.

### F. Cellular runtime and behavioral learning — staged local experiments

**Dependencies:** current Plasm/invariants, exact I4 layout, bounded task and explicit action broker. **Output sequence:** saved baseline and real task evaluator → exact candidate/input/weight checkpoint record → synchronized multiworker lanes → capability membrane → A/B quality/novelty → memory retrieval → adapter consolidation/decay. Preserve every rejected candidate's evaluation metadata and enough state for replay within retention budget.

**Acceptance:** no unready candidate can win; chosen weights reproduce the scored behavior; losing speculative lineages have no external effects; crash/timeout leaves stable state; budget is checked before expenditure; protected parameters demonstrably unchanged; restart reconstructs accepted state; task switches test both adaptation and retained skills. Run CPU on present hardware, then measure MPS independently. A norm can be one invariant, never a semantic-alignment certificate. Research aligned latent/KV transport against text and typed-protocol baselines before treating tensors as a universal communication language.

### G. Learned morphogenesis — research with a small runnable experiment

**Dependencies:** validated NCA reference implementation, explicit training objective and held-out perturbations. **Output:** trained rule and reproducible training/inference artifact; compare heuristic CA and trained NCA; optional visual decoder. **Acceptance:** growth/persistence/damage-recovery over held-out seeds/damage masks and long horizons; evaluate resizing, resource cost and failure shapes. Rendering a self-healing texture does not establish correct readable text or transactional UI. The browser component layer must keep action semantics intact.

### H. Replay, identity and authority — cross-cutting implementation/research

**Dependencies:** event/checkpoint schema, policy and cryptographic primitives with clear trust assumptions. **Output:** actual approval/denial/authority events, causal links, signed manifests, input/RNG/backend versions, bounded retention and replay checker. Distinguish payload integrity, publisher authentication, lineage attribution and decorative watermark. **Acceptance:** tampered or unauthorized actions rejected, replay detects missing inputs and nondeterminism, signatures bind exact artifacts and policy revision, and history can be inspected by humans. The original accountability request is satisfied by observable actions; arbitrary human/AI percentages are only a visualization if a method justifies them.

### I. Mesh and microkernel — later gates, not prerequisites for browser value

**Dependencies:** local runtime gates, explicit migration/consent policy under issue25, interoperable vector/checkpoint format. **Output:** typed loopback transport experiment first, then bounded consented peer exchange with authentication, replay defense, finite-value validation, backpressure, provenance and cancellation. RDMA is separate hardware/network work; browser users do not acquire raw POSIX privileges. Microkernel work begins with an emulator and capability specification after a useful existing-OS harness. **Acceptance:** adversarial transport and host-failure tests preserve ownership/teardown; no agent moves itself or model weights without the approved policy. A future custom kernel or chip requires its own device/driver/toolchain/security evidence and is not inferred from a Python process.
