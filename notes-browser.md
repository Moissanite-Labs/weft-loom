## Build phases for the browser discipline

1. **Reliable present surface**: review PR #46, correct artifact identity (issue #50), normalize raw/derived/fixture telemetry (#45), make failure/staleness visible. Exit: browser receives successive valid packets at root/nested routes, rejects malformed/hash failures, shows source/time, retains last accepted state, and recovers. No metric's unit changes silently across producers.
2. **Reusable procedural toolkit**: extract configured renderer lifecycle, geometry, SDF functions, aesthetic simplex, font and semantic DOM bridge without altering historical captures. Exit: mount/unmount repeatedly without workers/RAF/observers leaked; GPU failure can switch to working Canvas2D; scroll/keyboard/reduced-motion/high DPR/layout parity verified on current Chrome including owner's M1. Honor browser GPU limits independently of 64 GB unified memory.
3. **Maintained widgets and visual tests**: self-host pinned build dependencies, remove capture infrastructure in derived packages, preserve archive provenance, connect C3 trace viewer to real snapshots and step records. Exit: clean install/build, offline fixture gallery, controls work, visual semantics agree with code, rendered counts/hash identifiers come from real trace input or explicitly illustrative mode.
4. **Laya/model-responsive experiment**: distinct from scroll heuristic; pin checkpoint/tokenizer/runtime and browser acquisition/cache budgets. Measure cold/warm latency, memory, main-thread stalls, task utility, consistency, energy proxy and fallback. Feed only bounded schema-validated aesthetic suggestions with user override and stable reading layout. Exit: wins against simple heuristic on preregistered tasks without unacceptable regressions. A 64 GB host does not establish per-buffer WebGPU limits or model compatibility.
5. **Learned cellular surface experiment**: train small local-rule NCA separately from coordinate-target baseline. Test damage recovery, persistency, seed translation, held-out targets, asynchronous update rates and resource budget. A successful demo supplies data for a whitepaper claim; it is not evidence for evolved applications or biological identity.
6. **Spatial memory/evolving applications**: implement durable loci IDs, content/navigation schemas, history/undo, search, focus/keyboard and restoration first. Then bounded application adaptation with recorded objectives, isolated candidate state, A/B evaluation and rollback. Exit: users reliably retrieve/return to content; evolution improves task outcomes without destroying data or navigation. Actual OS integration and hardware acceleration consume these stable contracts later.
